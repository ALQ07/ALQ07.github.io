## js相关

1. **讲解一下js的原型链**
   要理解原型链，我们首先要弄清楚几个核心概念：`prototype` (原型)、`__proto__` (隐式原型) 和 `constructor` (构造函数)。
   ### 1. `prototype` (原型)
   - **是什么**：在JavaScript中，每个**函数**在创建时都会自动获得一个名为 `prototype` 的属性。这个属性是一个**对象**。
   - **做什么用**：这个对象是用来存放希望被该函数的**实例**所共享的属性和方法的。换句话说，通过这个构造函数创建的所有对象实例，都可以访问到它原型上的属性和方法。
   ```javascript
   function Person(name) {
       this.name = name;
   }

   // Person.prototype 就是一个对象
   // 我们可以在上面添加方法
   Person.prototype.sayHello = function() {
       console.log('Hello, I am ' + this.name);
   };

   console.log(typeof Person.prototype); // "object"
   ```
   ### 2. `__proto__` (隐式原型)
   - **是什么**：JavaScript中的每个**对象**（除了 `null`）都有一个内部的、隐藏的属性，通常可以通过 `__proto__` 来访问（标准推荐使用 `Object.getPrototypeOf()`）。
   - **做什么用**：这个属性指向创建该对象的**构造函数的** **`prototype`**。
   ```javascript
   // 使用上面的 Person 构造函数
   const person1 = new Person('Alice');

   // person1 是一个对象，它的 __proto__ 指向 Person.prototype
   console.log(person1.__proto__ === Person.prototype); // true
   ```
   简单来说，实例对象通过 `__proto__` 与它的构造函数的原型对象 `prototype` 连接起来。
   ### 3. `constructor` (构造函数)
   - **是什么**：在原型对象 `prototype` 上，有一个 `constructor` 属性。
   - **做什么用**：它默认指向该原型对象所属的**构造函数**本身。
   ```javascript
   console.log(Person.prototype.constructor === Person); // true
   ```
   这三者形成了一个闭环关系：
   - 构造函数 `Person` 有一个 `prototype` 指向原型对象。
   - 原型对象 `Person.prototype` 有一个 `constructor` 指回构造函数 `Person`。
   - 实例 `person1` 有一个 `__proto__` 指向原型对象 `Person.prototype`。
   ### 4. 原型链 (Prototype Chain)
   现在，我们可以定义**原型链**了。
   > 当我们试图访问一个对象的某个属性时，JavaScript引擎会首先在该对象**自身**上查找。如果找不到，它就会沿着该对象的 `__proto__` 属性所指向的原型对象上查找。如果原型对象上还是找不到，它会继续沿着原型对象的 `__proto__` 向上查找，直到找到该属性或者到达链的终点。
   > 这个由 `__proto__` 串联起来的对象链条，就是**原型链**。
   **原型链的终点是什么？**

   所有对象的原型链最终都会指向 `Object.prototype`，而 `Object.prototype` 的 `__proto__` 是 `null`，代表着链的终点。
   
2. **宏任务与微任务**
   要理解宏任务与微任务，首先要了解JavaScript的事件循环（Event Loop）机制。JavaScript是单线程的，但它通过事件循环实现了异步非阻塞I/O。事件循环中的任务有同步任务和异步任务，其中异步任务被分为两种类型：宏任务和微任务。
   ### 1. 什么是宏任务？
   宏任务可以理解为一个个独立的、由宿主环境（如浏览器或Node.js）发起的任务。每个宏任务执行完毕后，浏览器可能会进行一次UI渲染。

   **常见的宏任务包括：**
   - `script` (整个脚本的执行)
   - `setTimeout()` 和 `setInterval()`
   - I/O 操作（如文件读写、网络请求）
   - UI事件（如点击、滚动）
   - `requestAnimationFrame()` (特殊，在渲染前执行)
     宏任务会被放入一个“宏任务队列”中，事件循环会按顺序逐个取出执行。
   ### 2. 什么是微任务？
   微任务是在当前宏任务执行结束之后、下一个宏任务开始之前需要立即执行的任务。它们通常由JavaScript引擎自身触发，用于处理一些需要优先完成的异步操作。

   **常见的微任务包括：**
   - `Promise.then()`, `.catch()`, `.finally()`
   - `queueMicrotask()` (专门用来创建微任务的API)
   - `MutationObserver` (用于监听DOM变化)
   - `process.nextTick()` (Node.js环境中，优先级高于其他微任务)
     微任务有自己的“微任务队列”。
   ### 3. 事件循环的执行顺序
   这是面试的核心考点。事件循环的每一次迭代（tick）都遵循以下步骤：
   1. 从**宏任务队列**中取出一个任务并执行。
   2. 执行完毕后，检查**微任务队列**。
   3. **循环执行**微任务队列中的所有任务，直到队列被清空。如果在执行微任务的过程中又产生了新的微任务，它们也会被添加到队列末尾并被立即执行。
   4. （可选）执行UI渲染。
   5. 回到步骤1，开始下一次循环。
      **关键点**：一个宏任务 -> 所有微任务 -> 渲染 -> 下一个宏任务。
   **容易混淆的**：由于script代码块是一个大的宏任务，所以第一个执行的宏任务便是script。然后清空所有的微任务队列，最后才是宏任务队列，所以一般而言，我们在写代码时要记住：**微任务先执行，宏任务后执行**。

3. **promise有几种状态，状态之间的切换是可逆还是不可逆？**

   一个 Promise 对象有 **3 种** 状态，并且状态的切换是 **单向且不可逆的**。
   ### 1. Promise 的三种状态
   1. **Pending (进行中)**：这是 Promise 的初始状态。当一个 Promise 被创建时，它就处于这个状态，表示异步操作既没有完成也没有失败。
   2. **Fulfilled (已成功)**：也常被称为 Resolved。表示异步操作已成功完成。当 Promise 变为此状态时，会返回一个最终值（value）。
   3. **Rejected (已失败)**：表示异步操作失败。当 Promise 变为此状态时，会返回一个失败的原因（reason），通常是一个 Error 对象。
      `Fulfilled` 和 `Rejected` 这两种状态统称为 **Settled (已敲定)**。
   ### 2. 状态切换的不可逆性
   Promise 的核心特性之一就是它的状态一旦改变，就永远不会再变。这个过程是**不可逆的**。
   - 状态只能从 `Pending` 切换到 `Fulfilled`。
   - 或者从 `Pending` 切换到 `Rejected`。
     一旦 Promise 的状态变为 `Fulfilled` 或 `Rejected`，它就会被“锁定”，不能再回到 `Pending` 状态，也不能在 `Fulfilled` 和 `Rejected` 之间切换。

4. **内存泄漏的可能情况，怎么检测和排查？**

   ### 1. 常见的内存泄漏情况
   1. **意外的全局变量**：如果一个变量在函数作用域内没有用 `var`, `let` 或 `const` 声明，它会自动成为全局对象（如 `window`）的属性。如果这个变量引用了一个大对象，那么这个对象将永远不会被回收，直到窗口关闭。
   2. **未移除的事件监听器**：这是最常见的原因之一。当给一个节点或对象添加了事件监听器（如 `node.on(...)`），但在节点销毁时没有用 `node.off(...)` 移除，那么监听器的回调函数（通常是闭包）会一直存在，并且它所引用的任何外部变量都不会被释放。
   3. **未停止的计时器**：`setInterval` 和 `setTimeout` 的回调函数如果引用了外部对象，而计时器没有被 `clearInterval` 或 `clearTimeout` 清除，那么这些外部对象将无法被回收。
   4. **闭包的滥用**：闭包会使其函数内部可以访问外部函数作用域中的变量。如果闭包本身被长期持有（例如赋值给全局变量或作为事件监听器），那么它所引用的外部变量也会被长期持有，即使这些变量在其他地方已经不再需要。
   5. **静态对象引用**：在类的静态属性中缓存了大量的对象实例，但没有提供手动清理的机制。静态属性的生命周期与整个应用相同。
   6. **资源未释放**：在Cocos Creator中，通过 `assetManager` 或 `resources.load` 动态加载的资源，如果不再使用，需要手动调用 `assetManager.releaseAsset(asset)` 或对资源进行 `decRef()`（引用计数减一）来释放。否则它们会一直保留在缓存中，占用内存。
   ### 2. 如何检测和排查
   **工具：Chrome DevTools (开发者工具)**
   - **Performance Monitor (性能监视器)**
      - 打开 DevTools (`F12`) -> 点击右上角三个点 -> More tools -> Performance monitor。
      - 勾选 `JS heap size`。
      - 在你的游戏中反复进行某个操作（例如，反复打开和关闭一个UI界面）。
      - 观察 `JS heap size` 的图表。如果每次操作后，内存都上升到一个新的台阶并且在手动GC后（点击垃圾桶图标）不会回落到初始水平，那么很可能存在内存泄漏。
   2. **Memory Tab (内存面板) - Heap Snapshot (堆快照)**
      这是定位泄漏源头的关键工具。
      - **步骤**：
        1. 打开 Memory 面板，选择 `Heap snapshot`。
        2. **拍下快照 #1**：在执行任何操作之前，先点击 `Take snapshot` 按钮，作为基准。
        3. **执行可疑操作**：回到游戏，反复执行你怀疑导致泄漏的操作（如打开关闭UI）。
        4. **手动GC**：点击快照按钮旁边的垃圾桶图标 (Collect garbage)，强制进行一次垃圾回收。
        5. **拍下快照 #2**：再次点击 `Take snapshot`。
        6. **对比快照**：在快照列表中，选中快照 #2，然后在下方的下拉菜单中选择 `Comparison`，并与快照 #1 进行对比。
      - **结果分析**：
        - `Comparison` 视图会显示出在两次快照之间，哪些对象被创建了但没有被释放。
        - 重点关注 `Delta` 和 `New` 列。按 `Retained Size` (对象自身及它所引用的其他对象所占内存的总和) 排序，找到占用内存异常大的对象。
        - 点击一个可疑的对象，下方的 `Retainers` (引用者) 窗口会显示出一条引用链，告诉你**是谁在引用这个对象，导致它无法被回收**。顺着这条链往上找，通常就能找到泄漏的源头（比如一个未移除的事件监听器或一个全局变量）。
        - 在Cocos Creator中，你可能会看到很多 `cc_Node`、`cc_Sprite` 等对象。通过检查它们的属性（如 `_name`），可以定位到场景中的具体节点。

5. **简单讲一下js闭包**

   简单来说，闭包就是**内部函数用到了外部函数的变量**。
   ### 一个经典的例子
   ```javascript
   function createCounter() {
       let count = 0; // 'count' 是 createCounter 函数作用域内的一个局部变量

       // 下面这个返回的匿名函数就是一个闭包
       return function() {
           count++;
           console.log(count);
       };
   }

   const counter1 = createCounter(); // createCounter() 执行完毕，返回了内部函数

   // 此时 createCounter 的作用域已经结束，但它内部的变量 count 并没有被销毁
   // 因为返回的函数（现在是 counter1）仍然引用着它

   counter1(); // 输出: 1
   counter1(); // 输出: 2
   counter1(); // 输出: 3

   const counter2 = createCounter(); // 创建一个新的闭包环境
   counter2(); // 输出: 1 (和 counter1 的 count 是隔离的)
   ```
   ### 闭包的常见用途
   1. **数据私有化（模拟私有变量）**：如上面的计数器例子，外部无法直接访问或修改 `count` 变量，只能通过返回的函数来操作，实现了封装。
   2. **创建特定上下文的函数**：在循环中为回调函数绑定正确的值。
   3. **函数柯里化 (Currying)**：创建更专业化的函数。
   ### 缺点
   - 因为闭包会使其外部函数的变量一直保存在内存中，所以如果滥用，可能会导致内存消耗过大，甚至引发**内存泄漏**。特别是在不再需要闭包时，要确保其引用被解除（例如，将持有闭包的变量设为 `null`）。
   
6. **js引擎垃圾回收机制以及用到的算法**

   JavaScript开发者通常不需要像C/C++程序员那样手动管理内存，因为JS引擎会自动处理。这个自动化的过程就是垃圾回收。其核心任务是：**识别并释放不再被程序使用的内存**。
   ### 主要的垃圾回收算法
   1. **引用计数 (Reference Counting) - 已被淘汰**
      - **工作原理**：为每个对象维护一个“引用计数器”。当有一个引用指向该对象时，计数器加1；当引用被移除时，减1。当计数器变为0时，回收该对象。
      - **致命缺陷**：**循环引用**。如果两个对象相互引用，即使它们已经与程序的其他部分完全隔离，它们的引用计数也永远不会是0，导致内存泄漏。
   2. **标记-清除 (Mark-and-Sweep) - 核心基础**
      这是现代JavaScript引擎使用的核心算法。
      - **工作原理**：
        1. **标记阶段 (Mark)**：垃圾回收器从“根”开始，遍历所有可达的对象，并为它们打上“存活”的标记。
        2. **清除阶段 (Sweep)**：垃圾回收器遍历整个堆内存，回收所有没有被标记的对象。
      - **缺点**：**内存碎片化**。清除后，内存中会留下许多不连续的空闲空间。

5. **碰撞检测算法**

   为保证帧同步的确定性，我们的项目实现了一套碰撞检测算法。游戏场景中的碰撞盒可以分为圆形和矩形，矩形之间的碰撞使用SAT碰撞检测算法，圆形之间的碰撞直接使用距离比较法，圆形和矩形之间的碰撞直接找到矩形上的最近点然后比较。同时，当子弹移速过快的时候，使用射线检测的方式来规避子弹穿透问题。

   ### SAT分离轴定理
   如果两个矩形不相交，那么必然存在一条轴，使这两个矩形在这条轴上的投影也不相交。要想找到分离轴，只需要找到矩形的每一条边的法线，如果存在某一条边的法线使投影不相交，那么这两个矩形就是不相交的。

   ### 射线检测
   首先我们取子弹的上一帧的位置，然后从这个位置发射一条射线，射线会返回第一个交点的位置，我们计算上一帧的位置到交点之间的距离，如果这个距离小于子弹在这一帧移动的距离，那么说明子弹发生了碰撞。
